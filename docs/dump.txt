1. Document Overview & Design Conventions
This document defines the highly relational MySQL database schema for the four core modules of the TICH Enterprise Resource Planning (ERP) Platform: Administration, Academics, Finance & Fees, and Human Resources. Each module schema is presented as a set of normalised entity definitions, primary/foreign key relationships, index strategies, and business-rule constraints drawn directly from the verified system requirements.
1.1 Design Principles
Third Normal Form (3NF): All tables are in 3NF; lookup tables separate repeating data.
Entity Integrity: Every table has a surrogate primary key (id) plus natural keys where required.
Referential Integrity: Foreign keys enforce ON DELETE RESTRICT or SET NULL as appropriate.
Audit Trail: All mutable tables carry created_at, updated_at, and created_by.
Soft Deletes: is_active flag used for entities where hard delete is prohibited (regulatory requirement).
Code-First Enums: Low-cardinality status fields stored as VARCHAR with check constraints; no database ENUM type.
UUIDs for External Keys: Public-facing IDs (student reg numbers, invoice codes) stored as VARCHAR(50) with application-generated format.

17. Naming Conventions & Standards
17.1 Table Naming
Plural noun, snake_case: students, sacco_loans, staff_attendance
Junction/associative tables: <table1>_<table2> → registered_units
Avoid MySQL reserved words: use academic_rank, order_status instead of rank, order
Maximum 64 characters — keep names concise
17.2 Column Naming
snake_case throughout: registration_number, outstanding_balance
Surrogate PK always id: BIGINT UNSIGNED PK AUTO_INCREMENT
Foreign keys: <referenced_table>_id → student_id, staff_id, unit_id
Booleans: is_ prefix → is_active, is_cleared, is_published
Dates: _date suffix → admission_date, due_date, incident_date
Timestamps: _at suffix → created_at, updated_at, approved_at
References: _ref suffix → payment_reference, transaction_reference
Amounts: no prefix, stored as DECIMAL → amount, balance, outstanding_balance
17.3 General Rules
All monetary columns: DECIMAL(12,2) for KES; DECIMAL(14,2) for donor/project amounts
All dates: DATE; all timestamps: DATETIME
JSON fields used for truly dynamic, schema-less data only
No ENUM type in MySQL — use VARCHAR with application-enforced check constraints
Audit columns (created_at, updated_at, created_by) on all mutable tables
is_active TINYINT(1) DEFAULT 1 for all entities with soft-delete requirements
UNIQUE constraints enforced at DB level for all natural keys
All FK columns indexed for join performance
